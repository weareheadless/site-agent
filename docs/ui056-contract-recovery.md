## Read-only native timeout, spend, and resume audit

- Native direction calls `run_opencode_turn` at `hands/opencode_runner.py:2555–2576` with `execution_config` and direction kwargs, but does **not** pass `memory`; so its `record_usage()` finalizer has no memory sink and cannot log that direction turn's spend. The later implementation/build turn initializes `turn_kwargs` with context memory (around 2654–2670) and can be logged. Both calls use the `run_opencode_turn` watchdog: `timeout_seconds` or `builder.timeout_seconds` (default 1800), process-group termination, then `RunnerError` on timeout. Neither call supplies pre-call spend authorization or validation-repair budget.
- When a memory sink is present, OpenCode usage/cost is extracted from emitted events and `record_usage()` writes it to `Memory.log_llm_cost` as `origin="internal_builder"` after the turn. This is accounting, not a pre-call cap. `core.llm.LLMClient._check_budget()` checks rolling `llm_spend(since_hours=24)` before that client's `chat`/`chat_tools` requests. Native `run_opencode_turn` does not use that client or call `_check_budget`. It is therefore not existing enforcement for either native direction or its validation correction; the direction call additionally lacks accounting. Whether an existing policy can be safely shared is unresolved; no budget subsystem or policy is proposed here.
- `DesignService.execute_build` (`application/designs.py:1643–1704`) advances PLANNING to BUILDING **before** calling the builder and persists `build_request`/`build_target`. The native structured response is parsed only after the direction turn completes; integrated composition is persisted only after successful parse. On a thrown build error, `DesignJobWorker._run` transitions the run to FAILED (`application/design_jobs.py:682–697`). Restart handling is `DesignJobWorker._recover_queued` (`design_jobs.py:392+`): it re-enqueues created/assessing/planning runs with a queued event and PLANNING runs with persisted request/target; other BUILDING runs are marked INTERRUPTED (lines 424–430). Failed runs are not selected for resume. Thus the saved request/target and composition persistence are useful existing durability boundaries, but do not checkpoint/resume failed native parsing or establish repair identity/deduplication.
